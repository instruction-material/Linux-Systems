# User service comparison reference

The required unfinished task is message rendering; all input checks and the
driver are supplied. A valid finite app run produces its exact numbered rows.
The untouched learner exits 78 and the unit prevents a restart loop for that
status. Invalid settings exit 2.

This is a user manager and a user unit. The installed namespace changes only
the three %h/.local/share/linux-heartbeat path occurrences. The user identity
and required environment file remain explicit. Type=simple does not prove that
the app stayed running after a successful start command.

An active completed service has a real MainPID and journal rows. Persistent
enablement changes target activation links; it does not imply current running
state. Manual restart starts a new process. An unexpected SIGKILL is a failure
that on-failure restarts; explicit stop does not restart.

An invalid interval causes app status 2 and eventually reaches the bounded start
limit. Restoring the environment, clearing the failed state and starting again
produces new rows with the restored message. Unit changes require daemon-reload;
environment-file content changes require restarting the app.

Supply the actual versions, unit/process identities, states, journal rows,
enablement links, restart counts, failure diagnostics and cleanup evidence in
an independent saved record before comparing this explanation.
