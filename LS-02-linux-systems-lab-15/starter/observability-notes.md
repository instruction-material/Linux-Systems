# Independent automation and observability record

## 1. Environment, boundary and predictions
Record Linux, Python, manager/journal versions, active account, owned parent,
outside sentinel and the expected timer, process, output and policy relationships.

## 2. Ordinary run and the named repair
Retain the exact commands and source change. Separate timer trigger, actual
invocation, PID/UID, journal scope, process outcome and application evidence.

## 3. Changed anchor, data, order or budget
Explain each changed condition and compare actual records. Preserve the initial
observations. Do not reuse a historical run as evidence about a current one.

## 4. Refusal, interruption and actual retest
Record input guards and the live-worker interruption. Repeat normally and explain
which observations establish recovery and which only establish that a command ran.

## 5. Undo, cleanup and runbook limits
Retain exact unloaded unit names, stopped PIDs, empty parent, unchanged source and
outside sentinel. State the remaining operating assumptions and observation limits.
